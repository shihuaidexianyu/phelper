# v0.3.0 规划：验证债务清偿 + 架构还本

> 状态：草案（待范围确认后生效）

## 1. 定位与原则

v0.3.0 的主体不是新功能，而是**清偿 v0.2 的验证债务**。ogh-milestones.md 已经明确：v0.2 的自动切换、测量、MUX 生命周期等"代码闭环已存在"，但实际功耗对照、睡眠恢复、MUX 双向重启未验收，**不能宣称"已完整替代 OGH"**。在该状态清偿之前：

- 新增硬件写入功能（降压、超频、充电上限）不进 v0.3.0；
- 自动调度不扩大接管范围（Phase E 及以后视 Phase D 功耗数据决定）；
- 本轮所有代码工作服从既有不变量：AR-01～AR-12、§57 五阶段铺开、§60 审查清单。

## 2. v0.3.0 三条工作流

| 工作流 | 主题 | 是否需要硬件会话 |
|---|---|---|
| W-A | 硬件验证债务清偿（§3） | 是（管理员会话，一次性执行 milestones 5 步验收） |
| W-B | 架构还本（§4，2026-09 审查遗留） | 否（纯代码 + 回归测试，可在等待窗口穿插） |
| W-C | 自动调度 Phase B 收尾（§5） | 部分（F1/F2 纯代码；V6 功耗 A/B 需电池场景） |

MUX 桌面开放（§6）为条件项：仅当 V4 双向重启验证通过才生效。

| # | 项 | 步骤来源 | 通过标准 |
|---|---|---|---|
| V1 | OGH 顺序对照实测 | 步骤 2 | 固定场景 ≥3 轮，phelper 与 OGH 的平均 FPS、1% low、p95/p99、功耗、温度、风扇、节流原因全部入报告；不同轮次独立记录，不挑最好一次 |
| V2 | 睡眠/唤醒生命周期 | 步骤 3 | 唤醒后 Windows PPM 读回一致、恢复账本完整、心跳恢复；无恢复义务残留 |
| V3 | AC/DC 全流程 | 步骤 3 | 自动规则切换、手动覆盖、应用退出、正常退出各路径的恢复账本与 journal 证据完整 |

## 6. 条件项：MUX 桌面开放

代码侧已就绪（MuxLifecycle 持久记录 + 双向验证门 + desktop 只差解禁）。生效条件：

1. V4 双向重启验证通过且记录落盘；
2. 同主板、同 BIOS 核验通过；
3. 桌面写入仍走 `experimental-mux` 编译门 + 运行时双向验证记录门（现行为不变，仅开放 UI 入口）。

任一条件变化（BIOS 升级）则重新验证。

## 9. v0.4.0 前瞻（不承诺，仅登记）

- **降压调研（已搁置，2026-09-23）**：三轮调查（ABI 探明 / Intel UVP 表 / HP 先例外部验证）后用户裁决搁置。理由：**runtime 路径被 UVP+VBS 双锁**——Intel 配置表：UVP enabled 时无论 VBS 开关，runtime 降压均为 No；HP 笔记本 BIOS 不暴露 UVP 开关（Victus 案例证实 EFI 写保护连锁位变量都不可改），永不可达。唯一可达的 **BIOS 预启动路径（OGH 同款）需重启生效**，与 phelper 运行时透明控制 + 退出即恢复 + §56 证据链的产品形态不符，价值不成立。调查证据保留于 ogh-milestones.md（XTU 栈测绘：XtuService + iocbios2.sys + IntelOverclockingSDK + HPCreateService 工厂 + SdkWrapper 46 导出 + Platform.dll 21 导出；OGH 先例与 hpCpsPub BIOS 变量通道假设），若未来 HP 固件放开 UVP 或产品形态变化可复议。
- A1 旋钮宏收敛 + A5/A6 状态类型收敛（W-B 遗余）。
- 自动调度 Phase E 视 V6 数据决定。
- 安装包签名方案（证书来源待定）。
